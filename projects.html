BadToken HYDRA

Automated LLM red-teaming framework / Machine Psychology Group, Cyberpunk Division, UMass Boston

In active development

BadToken is a Python toolkit for adversarial testing of language models and the systems built on them. HYDRA is its evidence-aware engine: a scheduler that decides which attack module runs against which target, and a shared evidence format that every module writes into. The point is that an adversarial evaluation can be re-run and compared, rather than reconstructed from scratch each time.

The research question underneath it: when a model refuses a harmful request, is the refusal doing the work, or is the model simply unable to do the task? The first study answers it with a before/after weight-editing design, orthogonalizing the refusal direction and re-scanning, with encoding probes as a control.

Completed

  • ~20,000-prompt baseline across 20 garak probe families against a locally served instruction-tuned model.
  • Hit-log analysis that separates genuine guardrail failures from compliance markers inflating attack-success rates.
  • Z-score contextualization against a 23-model calibration baseline.
  • Serving stack on A100 nodes under Slurm, pinned (vLLM 0.6.3, torch 2.4.0, transformers 4.46.3) so results reproduce.

In progress

  • Before/after weight-editing study comparing refusal-mediated and capability-mediated resistance.
  • WebRedTeam module for prompt injection against LLM-backed web applications, including injection that escalates into script execution.
  • Cross-modal indirect injection: exploits carried in images rather than text.
  • Packaging as an installable library with a config-driven scan runner, structured result schema, and report generator.

CyberToolkit

Command-line network security utilities / Python

Public on GitHub

Embedded device and wireless security

Machine Psychology Group, Cyberpunk Division / faculty-supervised, isolated hardware bench

Ongoing

The hardware half of the same research: applying the offensive methodology behind BadToken to a physical attack surface, producing a device-security findings report as a companion to the LLM work. Being hands-on with techniques I read about in advisories means that when one shows up in an alert, I know what it looks like from the other side. Most recently: a captive-portal rogue access point, studying how client devices behave when they associate with a spoofed SSID and what they expose on join.

  • Rogue AP / evil twin: captive-portal access point capturing associating client MAC addresses and DHCP-assigned IPs to a live monitor
  • Wi-Fi auditing: scanning, packet capture, deauthentication, and handshake analysis with Marauder, aircrack-ng, and Kismet
  • Sub-GHz RF: capture and replay for access-control and keyfob research
  • RFID / NFC: credential read, clone, and modify workflows across low- and high-frequency tags
  • BadUSB / HID: scripted payloads for physical-access and endpoint-hardening testing

Scope and ethics. Every asset used is owned by or explicitly authorized for the research group, and all testing happens on an air-gapped bench. My faculty mentor reviews scope before each new exploit class, and any finding with real-world implications goes through coordinated disclosure. No third-party networks, no production systems, no unauthorized targets.
